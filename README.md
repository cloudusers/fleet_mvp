# 运力派单

输入是已经编好的配车单和司机当前状态。程序决定每张单给谁，以及什么时候把单发给这个司机。

派单单位是整组（一个配车单）。不拆组，也不把两组拼进同一趟。司机做完一组可以接龙下一组，站序保持原样。送机、接机、白天轮换用同一套损失 L，差别是方向和上一趟停在哪。

## 运行

在 `fleet_mvp` 目录下：

```bash
python3 run.py --real --alns    # 线上配车 + ALNS，默认 50 轮
```

`--peak`、`--trap`、`--real` 只能选一个。`--iters` 默认 50，`--seed` 默认 42。

终端先打汇总和每个司机的配车单，再写 `result/运力派单-YYYYMMDD-HHMMSS.xlsx`。文件名带到秒，撞名再加微秒，不覆盖上一份。`result/` 不进 git。

单测在仓库根目录跑：

```bash
python3 -m unittest discover -s fleet_mvp/test
```

线上四张表有更新时，在仓库根目录重新生成：

```bash
python3 fleet_mvp/data/build_0922.py
```

`test/` 里四张源表：

旅客姓名里，最后一个方括号前面的时间是到达该客人点的预估时刻。例如 `KIM JUKYOUNG(2,0+0券0免)【1836】【T1】2026-09-22 21:52:36[2026-09-22 23:30:00]` 的预估时刻是 `2026-09-22 21:52:36`。接机行经常没有末尾的 `[航班时间]`。

表里没有最晚时刻。`late = eta + LATE_SLACK_MIN`，分钟数在 `config.py`，现在是 10。站序按预估时刻排，同一时刻保持配车表上的先后。`s0922.xlsx` 有 2 笔订单没有出现在送机配车表里，没有收进编组。T1 / T2 都走 `TRANSFER_STATION`。有 8 站的预估时间在 9月20日或 9月21日，原样保留，所以这批司机的班次是 `2026-09-20 20:00` 到 `2026-09-23 02:00`。生成结果：26 个司机，156 个配车单（送机 85 / 接机 71），318 个客人。

## 输入

`stops` 只写客人点。中转站不进列表，方向看 `kind`。

| | 送机 `to_station` | 接机 `from_station` |
|--|-------------------|---------------------|
| 路线 | 客人点 … → T | T → 客人点 … |
| `eta` | 预估接客 | 预估送达 |
| `late` | 最晚接客，硬约束 | 最晚送达，硬约束 |

L 按每一位客人累计。整组插入或放下，站序和客人名单不改。一组跑完后的位置和时刻是下一组的起点。

司机字段：姓名、车号、GPS、`current_gid`、接或送、`free_at`、`on_shift`、`shift_start` / `shift_end`。身份按电话，不按车号。同一个人当天开过别的车，写在 `note` 里。

进候选之前先看班次：

- `on_shift=false` 不进。
- 可出发时刻已经到了或过了 `shift_end`，不进。
- 首客 `eta` 已经到了或过了 `shift_end`，不进。
- 可出发时刻已经晚于首客 `late`，不进。这段不看路程，路程在模拟里判。

班内出发、下班后才收车的仍然派，日志写加班，L 加加班分钟。空闲的下一单从 GPS 出发。运送中的下一单从本趟终点出发（送机是 T，接机是最后一户），时刻是 `free_at`，早于上班则等到上班。正在跑的组锁在队首，不能改派。

## 损失

优化的是整张派单表：

\[
L(\text{方案})=\sum_{\text{已派}}L(d,g)+\sum_{\text{未派}}(\theta_{\text{miss}}+\theta_p\cdot\text{人数})
\]

一单：

\[
L(d,g)=\theta_e\,t_{\text{空驶}}+\theta_u\,k_{\text{不顺路}}+\theta_\delta\,t_{\text{晚点}}+\theta_w\,t_{\text{空等}}+\theta_r\,r_{\text{松弛}}+\theta_{ot}\,t_{\text{加班}}
\]

任一站超过自己的 `late`，或出发时刻已经到了下班，这一单不可行，方案记 `1e12`。人数不跟座位比，没有超载。没人接的组进未派，用未派罚分压进总账。组内载客公里不进 L，它只影响后面会不会晚、这趟什么时候结束。

空驶起点：

| 上一趟 → 下一单 | 空驶 |
|-----------------|------|
| 送机 → 送机 | T → 下一组首个酒店 |
| 送机 → 接机 | 已在 T，约 0 |
| 接机 → 接机 | 上一户 → T |
| 接机 → 送机 | 上一户 → 下一酒店，同址约 0 |

权重在 `loss.py` 的 `LossWeights`。越不能容忍的项，权重越大。

| 项 | 权重 | 算法 |
|----|------|------|
| 空驶 | 1.2 / 分钟 | 空车开到这单开始载客的点。送机是去首个酒店，接机是回 T |
| 不顺路 | 2.0 / 公里 | 只计送机：从当前位置绕去首个酒店再去 T，比直奔 T 多出来的公里。人已经在 T 附近（`AT_TRANSFER_KM`，0.4 km）记 0。接机记 0 |
| 晚点 | 6.0 / 分钟 | 每位客人 `max(0, 到达 − eta)` 之和 |
| 空等 | 3.0 / 分钟 | 每位客人 `max(0, eta − 到达)` 之和。人已经空出来、还没到建议出发的那段不算 |
| 松弛不足 | 0.8 / 分钟 | 每位客人距自己 `late` 不足 8 分钟的部分之和 |
| 加班 | 2.0 / 分钟 | 班内出发、收车晚于 `shift_end` 的分钟 |
| 未派组 / 人数 | 10000 / 80 | 放下的组数和人数 |

行驶按直线、28 km/h。停靠：接客 3 分钟，送达 5 分钟，接机在站内上车 3 分钟。

## 发单时刻

```
建议出发 = max(可出发时刻, 刚好赶上首站 ETA 的出发时刻)
建议派单 = 建议出发 − 5 分钟
最晚出发 = 再晚就会有一站超过 late
```

提前出发会在客人点空等，空等进 L。晚于最晚出发则这单不可行。发单时刻不会早于当前时刻和可出发时刻，也不会晚于出发时刻。最晚出发要二分大约 24 次，搜索时不算，只在最后打印和写表时算。窗口里没有可行出发点时，这一列留空。

## 搜索

贪心按首站 ETA 依次插入，每个组放到当前总账最小的位置。

`--alns` 在贪心结果上继续搜。每轮用轮盘抽一个破坏算子：随机拆、拆当前最亏的几组、拆预估时刻靠近的几组。拆下大约两成已派组，连同原来的未派组按 regret-2 插回去。只有一个司机接得上的组 regret 记 `1e12`，先插。

三个算子初始权重都是 1。每 10 轮更新：新的全局最优 5 分，优于当前解 3 分，模拟退火接受了更差解 1 分。下一段权重是 `0.8 * 旧权重 + 0.2 * 本段平均得分`，下限 0.05。退火温度从 60 开始，每轮乘 0.97。

比较用的是同一个 L。试插入时只重算被改到的那条司机链、从插入点往后的部分。

进度：开始一行，之后每 10 轮一行，出现更优解时一行，结束再一行。

## 输出

日志按司机分块：姓名、车号、配车单号、送机/接机、建议派单、出发、最晚出发。每个客人一行：姓名、人数、预估接客或送达、地址、纬度、经度。时间格式 `月-日 时:分`。锁定的组标成当前在跑。没人接的单列在最后，司机格写未派。

xlsx 一个客人一行，列是：司机、车号、配车单号、送迎、建议派单、建议出发、最晚出发、站序、客人、订单号、人数、地址、纬度、经度、预估时间、时间含义。

## 限制

- 行驶是直线、均速 28 km/h，不是路网，也不是 Google ETA。
- 还没有「已发单冻结、其余按 GPS 滚动重派」。这是派单引擎，司机实时位置要外面送进来。
- 日志给的是派单结果和总 L，没有把落选司机的 L 拆开。`rank_candidates` 还在，入口没用。
- 权重是初值，要用线上的准点、空驶、空等再标。
- 忙闲均衡没做。
- 没有车容量。人数只参与未派罚分和输出。
- 发车前停在原地的时间不进 L。一条很松的任务链把人占住时，总账看不出他本来可以去跑别的组；只有插不进去、晚点或加班才会体现出来。

输入是配车单（包括分组和时间预估等信息）和司机状态（少了运行中的车辆GPS，目前都是中转站）。算法决定每张单给谁，以及什么时机给司机合适。即派单给谁、什么时候派

# 一、派单给谁

派单单位是整组（一个配车单）。不拆组，也不把两组拼进同一趟。司机做完一组可以接龙下一组，站序保持原样。送机、接机、白天轮换用同一套损失 L，差别是方向和上一趟停在哪。

## 运行

```bash
python3 run.py --real --alns    # 线上配车 + ALNS，默认 50 轮
```

自测时拉取的线上四张表(接送机分组输入的数据、接送机配车导出的数据),放在data目录下，后面如果有更新，可以用重新下载某天数据并执行

## 数据
| 文件 | 用途 |
|------|------|
| `data/drivers_0922.json` | 9月22日司机。坐标暂时用的中转站,替换成实时获取司机定位 |
| `data/groups_0922.json` | 9月22日配车单。`note` 里是线上当时的司机 |

`test/` 里四张源表：

- `s0922.xlsx`、`j0922.xlsx`：订单数据。用 `order_no` 对客人，取 `allocation_no`、`departure_address`、`departure_location`。坐标在表里是 `经度,纬度`。

旅客姓名里，最后一个方括号前面的时间是到达该客人点的预估时刻。例如 `KIM JUKYOUNG(2,0+0券0免)【1836】【T1】2026-09-22 21:52:36[2026-09-22 23:30:00]` 的预估时刻是 `2026-09-22 21:52:36`。

## 输入
`stops` 只写客人点。中转站不进列表，方向看 `kind`。 

| | 送机 `to_station` | 接机 `from_station` |
|--|-------------------|---------------------|
| 路线 | 客人 - T | T - 客人 |
| `eta` | 预估接客 | 预估送达 |
| `late` | 最晚接客 | 最晚送达 |

L 按每一位客人累计。整组插入或放下，站序和客人名单不改。一组跑完后的位置和时刻是下一组的起点。

司机字段：姓名、车号、GPS、`current_gid`、接或送、`free_at`、`on_shift`、`shift_start` / `shift_end`。身份按电话也可按车号。同一个人当天开过别的车，写在 `note` 里。

进候选之前先看班次：
- `on_shift=false` 不进。
- 可出发时刻已经到了或过了 `shift_end`，不进。
- 可出发时刻已经晚于首客 `late`，不进。

首客预估在下班之后，只要建议出发还在班内，仍然派。班内出发、下班后才收车的记加班，L 加加班分钟。空闲的下一单从 GPS 出发。 

运送中（`enroute`，并带本趟终点）的下一单从终点出发，时刻是 `free_at`，早于上班则等到上班。

正在跑的组锁在队首，不能改派。空闲却带 `current_gid` 直接报错，不会把那张单锁成已完成。

## 损失
即全局视角，优化的是整张派单表：

一单：L(d,g) = θe·空驶 + θu·绕路 + θδ·晚点 + θw·空等 + θr·松弛 + θot·加班

整体：L(方案) = ΣL(d,g) + 未派罚。


任一站超过自己的 `late`，或出发时刻已经到了下班，这一单不可行，方案记 `1e12`。没人接的组进未派，用未派罚分压进总账。组内载客公里不进 L，它只影响后面会不会晚、这趟什么时候结束。

空驶起点：

| 上一趟 - 下一单 | 空驶 |
|-----------------|------|
| 送机 - 送机 | T - 下一组首个地址 |
| 送机 - 接机 | 已在 T，约 0 |
| 接机 - 接机 | 上一组末尾地址 - T |
| 接机 - 送机 | 上一组末尾地址 - 下一组首个地址，同址约 0 |

权重在 `loss.py` 的 `LossWeights`。注：**越不能容忍的项，权重就要配的越大。**

| 项 | 权重 | 算法 |
|----|------|------|
| 空驶 | 1.2 / 分钟 | 空车开到这单开始载客的点。送机是去首个酒店，接机是回 T |
| 不顺路 | 2.0 / 公里 | 只计送机：从当前位置绕去首个酒店再去 T，比直奔 T 多出来的公里(当前到首址距离 + 行程到中转站全程距离 - 当前到中转站距离)。  人已经在 T 附近（`AT_TRANSFER_KM`，0.4 km）记 0。接机记 0 |
| 晚点 | 6.0 / 分钟 | 每位客人 `max(0, 到达 − eta)` 之和 |
| 空等 | 3.0 / 分钟 | 每位客人 `max(0, eta − 到达)` 之和。人已经空出来、还没到建议出发的那段不算 |
| 松弛不足 | 0.8 / 分钟 | 每位客人距自己 `late` 不足 N分钟的部分之和（N例如是8分钟） |
| 加班 | 2.0 / 分钟 | 班内出发、收车晚于 `shift_end` 的分钟 |
| 未派组 / 人数 | 10000 / 80 | 放下的组数和人数 |

行驶距离和时间真实按google，其次可以路网，如果都失败可以按直线（例如30 km/h）


## 搜索
贪心按首站 ETA 依次插入，每个组放到当前总账最小的位置。

`--alns` 在贪心结果上继续搜。每轮用轮盘抽一个破坏算子：随机拆、拆当前最亏的几组、拆预估时刻靠近的几组。拆下大约两成已派组，连同原来的未派组按 regret-2 插回去。只有一个司机接得上的组 regret 记 `1e12`，先插。
三个算子初始权重都是 1。每 10 轮更新：新的全局最优 5 分，优于当前解 3 分，模拟退火接受了更差解 1 分。下一段权重是 `0.8 * 旧权重 + 0.2 * 本段平均得分`，下限 0.05。退火温度从 60 开始，每轮乘 0.97。

注：**比较用的是同一个 L**。试插入时只重算被改到的那条司机链、从插入点往后的部分。
进度：开始一行，之后每 10 轮一行，出现更优解时一行，结束再一行。

## 输出
日志按司机分块：姓名、车号、配车单号、送机/接机、建议派单、出发、最晚出发。

每个客人一行：姓名、人数、预估接客或送达、地址、纬度、经度。时间格式 `月-日 时:分`。锁定的组标成当前在跑。没人接的单列在最后，司机格写未派。
xlsx 一个客人一行，列是：司机、车号、配车单号、送迎类型、建议派单、建议出发、最晚出发、站序、客人、订单号、人数、地址、纬度、经度、预估时间、时间含义。表格对应当次参数：默认贪心，`--alns` 就是 ALNS。

## 限制
- 行驶路线优先google或路网，有问题再直线代替（如均速 30 km/h）
- 权重是初值，可以查下线上的准点、空驶、空等数据反推下权重设置多少合适。
- 忙闲均衡没做。
- 发车前停在原地的时间不进 L。一条很松的任务链把人占住时，总账看不出他本来可以去跑别的组；只有插不进去、晚点或加班才会体现出来。

# 二、派单时机

L 决定这张单给谁。时机是派定之后，这个司机什么时候走、什么时候收到消息。路线时间即路线分钟应该按google调用或路网分钟（如果调用失败兜底的话可以用直线代替、比如30 km/h：`路线分钟 = 直线公里 / 30 × 60`。

```
能走的时刻 =
  空闲状态        max(预估时刻, 上班时刻)    位置 = 当前 GPS
  正在接送        本趟结束时刻              位置 = 本趟终点
  已排前面的趟  上一趟收车时刻               位置 = 收车地点

可出发 = max(能走的时刻, 现在)

送机路程 = 路线分钟(司机的位置, 第一位客人)
接机路程 = 路线分钟(司机的位置, 中转站) + 路线分钟(中转站, 第一位客人)

建议出发 = max(可出发, 第一位预估 − 路程)
建议出发 <= 最晚出发，否则不派、不通知

通知 = min(建议出发, max(建议出发 − 5~10 分钟, 可出发))
```


最晚出发：离开后，每位客人仍不晚于自己的预估加 10 分钟，这些离开时刻里最晚的一个。早到某一位，就等到他的预估时刻再开下一位。

```
到达下一位 = max(到达这位, 这位预估) + 到下一位的路线分钟
送机收车 = max(到达末位, 末位预估) + 末位开回中转站      司机回到中转站
接机收车 = max(到达末位, 末位预估)                     司机留在末位地址
```
